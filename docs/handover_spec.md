# 左手デバイス近代化改修ファームウェア開発 引き継ぎドキュメント

## 1. プロジェクト概要

PIC18F2450（5V系）を搭載していた既存の一点物左手コントローラーからメインマイコンを撤去し、**Waveshare RP2040-Zero** に換装してファームウェアを刷新・近代化するプロジェクトです。
通常のキースイッチ入力に加え、**2軸アナログスティックの傾き量に応じた多段階キー入力（歩き／走り等の切り替え）** を実現します。

---

## 2. ハードウェア仕様・ピンアサイン

### 2.1 マイコンボード

* **モデル:** Waveshare RP2040-Zero
* **動作電圧:** 3.3V系
* **USBコネクタ:** オンボード USB Type-C

### 2.2 電気的接続仕様

* **スイッチ入力（合計13個）:**
  * 外付け集合抵抗（プルアップ）は撤去。
  * RP2040の **内蔵プルアップ抵抗（Software Pull-up）** を有効化。
  * スイッチ押下時に **GNDへ短絡（アクティブLOW）**。
* **アナログジョイスティック（2軸可変抵抗）:**
  * 電源はRP2040の **3.3V（3V3ピン）** と **GND** に接続（5V印加厳禁）。
  * スライダー出力をADCピンへ直結。

## 3. ファームウェア機能要件

### 3.1 デバイス動作モード

* **USB Composite Device:**
  * 標準キーボード（HID Keyboard）
  * オプション：ゲームパッド（HID Gamepad / Joystick）

### 3.2 アナログスティック多段階キー判定仕様

アナログスティックの各方向（上・下・左・右）への倒しこみ量に応じて、送信するキーコードを切り替えます。

1. **ゼロ点自動キャリブレーション:**
   * 起動時に一定時間（数十ms）スティックの静止値を読み取り、ニュートラル中心値（Center Offset）として記録。
2. **デッドゾーン（遊び）の設定:**
   * 中心値付近の微小ノイズをカットし、ニュートラル時は全キー解放。
3. **ヒステリシス（閾値チャタリング防止）:**
   * ON閾値とOFF復帰閾値にマージン（例: 5〜10%）を設け、境界値での高速連打・誤判定を防止。
4. **多段階入力ロジック（例：Y軸・前方向）:**
   * **ニュートラル:** キー全解放
   * **閾値1（浅倒し / 歩き）:** `W` キーを押下
   * **閾値2（深倒し / 走り）:** `Shift` ＋ `W` キーを押下
   * ※斜め入力（X軸＋Y軸の同時成立）時は、両軸の判定を合成して送出。

## 4. 設定管理・外部連携インターフェース設計

### 4.1 設定パラメータ（JSON構造例）

```json
{
  "keymap": {
    "buttons": ["1", "2", "3", "4", "5", "6", "7", "8", "9", "Space", "Tab", "LCtrl", "LAlt"]
  },
  "joystick": {
    "deadzone": 4000,
    "hysteresis": 1500,
    "directions": {
      "up": {
        "th_walk": 12000,
        "th_run": 26000,
        "key_walk": "W",
        "key_run": ["Shift", "W"]
      },
      "down": {
        "th_walk": 12000,
        "th_run": 26000,
        "key_walk": "S",
        "key_run": ["Shift", "S"]
      },
      "left": {
        "th_walk": 12000,
        "th_run": 26000,
        "key_walk": "A",
        "key_run": ["Shift", "A"]
      },
      "right": {
        "th_walk": 12000,
        "th_run": 26000,
        "key_walk": "D",
        "key_run": ["Shift", "D"]
      }
    }
  }
}
```

### 4.2 設定同期インターフェース方針

1. **CircuitPython / KMK 構成時:**
   * ストレージ上の `config.json` を直接読み書き可能とする。
   * ブラウザ連携を行う場合は、**Web Serial API** 経由でシリアル通信を行い、JSON文字列の受け渡しによって設定保存とホットリロードを実行。
2. **C/C++ (TinyUSB / QMK派生) 構成時:**
   * **Raw HID（32バイト固定長パケット）** ハンドラを実装し、WebHID API対応の専用WebUIと通信。
   * 設定値はRP2040の内蔵Flash（EEPROMエミュレーション領域）へ永続化。

## 5. 実装フェーズ・タスク一覧

* **Phase 1: ハードウェア検証 & ADCプロファイリング**
  * 各GPIO（GP0〜GP12）のスイッチ入力導通テスト。
  * スティック（GP26, GP27）のADC生値（最小・最大・中心・ノイズ幅）をシリアル出力して物理特性を把握。
* **Phase 2: スティック多段判定エンジンの実装**
  * ヒステリシス付きステートマシン（Neutral / Zone1 / Zone2）の単体モジュール作成。
  * キー押下・解放の競合回避（Zone1からZone2への遷移時に一度キーを離すか同時押しにするかの制御）。
* **Phase 3: デバイス統合 & デバウンス処理**
  * ボタン13個のデバウンススキャン処理とスティックスキャンの統合。
  * USB HIDレポート送信の安定化。
* **Phase 4: 設定UI・外部連携**
  * 設定ファイルのローカル永続化。
  * ブラウザから閾値・キーバインドを調整する専用設定ツールの作成。
